fix: 安装脚本补端口预检与健康自检（修一个真实踩到的静默失败）

起因是实际部署时的一次故障：服务端装完服务显示 Running、日志干净，
但控制台怎么登都登不上。真实原因是 8080 被 Everything 的内置 HTTP 服务
占用——Windows 上 Go 程序 bind 时对方也在 LISTEN，bind 依然成功
（SO_REUSEADDR），请求随后被两个 socket 随机分流。用户一半概率在向
Everything 的登录框提交我们的口令，全程无任何报错。

install-server.ps1：
- 新增 Get-PortOccupiers：列出占用者 PID / 进程名 / 路径，
  自动排除 AgentMeshServer 自身进程（重装时它正在跑很正常，不该被自己吓到）
- 冲突即中止，打印进程清单并给出当前空闲的候选端口；加 -Force 可跳过预检
- 新增健康自检：轮询 /healthz 至多 5 次，要求状态码 200 且响应体匹配
  {"status":"ok"}。只校验状态码不够——别人抢了端口时对方同样会返回 200
- 清理针对旧端口的防火墙遗留规则，避免反复换端口后堆积暴露面
- 端口预检刻意放在写配置、复制文件之前：冲突时不动任何东西

install-client.ps1：
- 安装前 TCP 探服务端可达性（跨网段 / NAT / 端口写错 / 服务端未起
  表现完全一样，都只是连不上）
- P2P 端口冲突只警告不中止：文件传输可走服务端中转兜底
- 启动后扫日志有无 connection refused / i/o timeout / x509 等连接类报错
  并回显最后三条；服务 Running 只说明进程活着，说明不了它连得上中枢

过程中修掉两个自检自身的坑，否则它会假阳性：
- $resp.Close() 之后再读 StatusCode，对象已释放恒为 0，健康自检永远失败
- HttpWebRequest 默认套用 IE 代理；ProxyOverride 里 "127.*" 这类带通配符的
  项在 .NET 下并不可靠——本机开着 clash-verge 时，连一个没人监听的端口也能
  拿到 200。必须显式 $req.Proxy = $null

验证（本机实机，非模拟）：
- 空闲端口返回 0 占用者；被占用的 3389 能报出 svchost.exe
- 自身服务在 8080 监听时 Get-PortOccupiers 返回 0（排除逻辑生效）
- 健康自检：8080 判定本服务，8099 / 5000 判定非本服务
- 不可达端口返回可读报错；候选端口确实空闲
- 三个安装脚本语法解析均无错误
