## 0. 一句话定位

> **企业 AI 使用能见度与防泄密审计平台——装在被审计的电脑上，不碰网络、不装浏览器插件，十分钟上线。**

三个定语各自对应一条护城河，缺一个这个定位就散了：

| 定语 | 对应护城河 | 谁给不了 |
|---|---|---|
| **装在电脑上**（端点层） | 能读到 IDE/CLI 的真实会话与本地"记忆文件" | 浏览器扩展派（Aona/LayerX/Purview）读不到本地文件 |
| **防泄密审计**（不是监控聊天） | 强制脱敏 + 只报风险不报原文，员工抵触小、合规站得住 | 纯"上网行为管理"类产品 |
| **十分钟上线** | Go 静态单文件 + 自带 TLS + 跨网方案 | 汇智（Nuitka 冻 Python 110 MB）、shadow-ai-guard（K8s+Loki+Grafana） |

## 1. 先划市场边界：能卖给谁，不能卖给谁

**这一节比后面所有技术内容都重要。** 端点路线的覆盖面有硬边界，卖错客户不是"功能不够"，是**装完发现什么都采不到，售后必然崩**。

### ✅ 该卖（甜点客户）

| 特征 | 为什么 |
|---|---|
| **20–200 人，有研发 / 设计 / 内容团队** | 这类人用 Cursor / VS Code / Claude Code / Codex CLI —— 恰是**明文落盘**的那批（实测见 `GOAL.md` §8） |
| **有值得保护的资产**：代码、图纸、客户名单、报价、财务模型 | 泄密恐惧真实存在，P1 痛点成立 |
| **多厂区 / 多办公室 / 出差多** | 跨网是我们的独占项，汇智和开源都推给客户 |
| **已有 AI 采购**（Cursor 企业版、Copilot 席位） | P3/P4 痛点（账号、席位浪费）才成立，才谈得上 ROI 故事 |

典型画像：软件外包公司、制造业研发部、设计/建筑工作室、电商代运营（你自己就是这类）。

### ❌ 不该卖（会翻车）

| 特征 | 为什么翻车 |
|---|---|
| **全员只用网页版豆包/ChatGPT** | 实测：豆包本地 16 个 LevelDB 文件含连续 20+ 汉字 **0 个**；WorkBuddy 本地**连会话库都没有**（在云端）。我们采不到，装完只能报"检测到安装"，客户立刻觉得被骗 |
| **想要实时阻断**（粘贴身份证当场拦下） | 架构做不到。汇智也做不到（它本质是脱敏 + 审计威慑）。卖之前必须讲清 |
| **要"看员工聊天原文"** | 这是监控产品，法律风险与员工抵触都会反噬。我们只报**风险命中**，不报原文 |

> ⚠️ **销售纪律**：签约前必须跑一次 `tools/probe_readability.py` 看客户机器到底有多少可读源。
> 可读源 ≈ 0 的单子不要接——不是我们不行，是端点路线对那台机器不适用。
> 这条会挡掉一些单子，但挡掉的正是那些装完就要退款的。

### 落地阻力：员工凭什么让装（**这一节此前完全空白**）

**先把命题纠正**：不该问"怎么让员工想装"——**员工永远不会自愿想被审计**。
正确的问题是"怎样让装这件事不发生对抗"。依赖"员工自愿安装"的商业模式不成立。

#### 三条路径，缺一不可

| 路径 | 做法 | 解决什么 |
|---|---|---|
| **① 强制部署**（主力） | 域控 GPO 批量推送 / MDM（Intune、企微钉钉设备管理）/ 入职标配写入《员工手册》 | 覆盖率。这才是端点产品的真实落地方式——Fleet、osquery 从来不求"员工想装" |
| **② 知情告知**（合规底线） | 装前公示采集范围与不采集清单，员工签收 | 《个保法》合法性基础。**公司设备上**企业管理权成立；**员工个人设备**须单独同意 |
| **③ 正向叙事**（降抵触） | 员工可自助查看"我自己的数据"；AI 提效度量作为绩效佐证 | 把"被审计"变成"被看见" |

#### 由此倒推出一条客户硬约束（**修正 §1 画像**）

**目标客户必须有 IT 管理能力**（域控 / MDM / 专职 IT）。
没有的（20 人以下、无 IT 岗）——**装不上，别卖**。这比"有没有研发团队"更刚性。

#### 产品侧必须做的三件事（决定抵触强度）

1. **只报风险命中，不报原文**——能下钻到"哪个客户端 / 哪台机器 / 什么时间"，但看不到那句话本身。
2. **员工可自查自己的数据**——不能看别人的。透明度是对抗敌意的唯一解药。
3. **公开"不采集清单"**：不截屏、不键盘记录、不读浏览器历史、不碰个人聊天 App。
   这是与深信服 / IP-guard 那类名声很差的产品划清界限的关键——它们坏的口碑正来自截屏 + 键盘记录 + 聊天原文。

#### 反卸载：只防随手关闭，不防决心规避

服务以 SYSTEM 运行、卸载需管理员口令、心跳缺失在控制台告警（"这台机器 24 小时没上报"）。
**别向客户承诺 100% 覆盖**：员工真要规避，换个人手机、用网页版就绕过去了。
**诚实定位 = 公司设备全覆盖**，不是"全渠道无死角"。
shadow-ai-guard 那条"干净 vs 坏了"的洞察在这里也成立：覆盖率页必须能区分"没人用 AI"和"客户端被关了"。

## 2. 企业主痛点排序（以及我对你上一轮判断的一处修正）

| 序 | 痛点 | 老板的原话 | 首单还是续费 |
|---|---|---|---|
| **P1** | **泄密** | "我们公司的代码/客户名单，是不是被员工喂给 AI 了？" | **首单**（恐惧驱动，掏钱最快） |
| **P2** | **能见度** | "公司到底谁在用 AI、用了哪些、有没有失控？" | 首单（管理刚需） |
| **P3** | **账号与席位** | "我花钱买了企业版，员工是不是登自己的账号？" | 首单（一说就懂，落差感强） |
| **P4** | **追溯与合规** | "出事能不能查到是谁、什么时候、什么内容？" | 合规刚需（《个保法》语境） |
| **P5** | **用量与成本** | "AI 花了多少钱，值不值？" | **续费**（ROI 故事，不是首单理由） |

### 一处修正：日报是"续费理由"，不是"首单理由"

你上一轮判断"对话采集 + 日报是商业化核心"——**方向对，但顺序要调**。

- **日报回答的是 ROI**：每月 AI 花多少、哪些席位浪费了。对 20–200 人的公司，这笔钱目前还没到"心疼"的程度，**它是让老板第二年续费的故事，不是让他今年掏钱的理由**。
- **真正让他掏钱的是恐惧**：公司代码进了别人的模型。这个念头一旦被种下，当天就想装。
- 两者共用同一套采集管道（会话 + 记忆文件 + 脱敏），**技术上不冲突，只是演示顺序不同**。

**所以销售演示的第一页应该是"风险"，不是"用量"。** 日报放在最后当加分项："顺便，这些还能帮你算出哪些席位白买了。"

## 3. 三方能力矩阵对照

| 能力 | 汇智中枢 | shadow-ai-guard | 我们（现状 → 目标） |
|---|---|---|---|
| **部署形态** | Nuitka 冻 Python，单文件 110 MB | K8s + Loki + Grafana | ✅ Go 静态单文件 ~24 MB，自带 TLS（**三方最优**） |
| **入网** | 邀请码 + 落地页 + 客户端分发 | 无（假设已装 agent） | ✅ 已有，`max_uses` → **V1 改一次性单设备** |
| **AI 客户端清单** | 有（agent_detect + inventory） | 有（registry，7 类证据源） | ⚠️ 15 个硬编码 → **V1 下沉服务端** |
| **登录账号识别** | 未见 | ✅ `~/.claude.json` 判账号 | ❌ → **V1 新增（P3 痛点，一说就懂）** |
| **对话采集** | 有，脱敏后空条目丢弃 | 有（IDE + CLI 证据源） | ⚠️ → **V2 做**（Codex/Cursor/Windsurf/VS Code 已实测可读） |
| **"记忆文件"扫描** | 未见 | 未见 | ❌ → **V2 首发（两家都没有，业务浓度最高）** |
| **脱敏** | `runtime/redact.py`，强制 | 有 | ✅ `core/redact.go` 已挂上报唯一出口（G-2 完成） |
| **用量/日报** | `/api/harvest/daily-digest` | 预算视角 | ❌ → **V4**（Codex JSONL 自带 token） |
| **采集源健康（干净 vs 坏了）** | 未见 | ✅ 每源上次上报时间 | ❌ → **V1**（正中我们软肋：服务 Stopped 却显示"没人用 AI"） |
| **多用户 RBAC** | ✅ `*_own`/`*_all` 成对权限 | 无 | ❌ → **V3**（`store/users.go` 已写 536 行，未接线） |
| **授权/档位/席位** | ✅ Ed25519 离线授权 + 绑机 | 无 | ❌ → **V3** |
| **监控指标** | `/api/metrics/prometheus` | Grafana | ❌ → **V3** |
| **错误码契约** | ✅ 前端只做映射 | 无 | ❌ → **V3** |
| **中枢侧 MCP 编排** | ✅ `mesh_*` 工具 + dry-run + 风险分级 | 部分 | ❌ → **V5（架构性跨越）** |
| **跨网** | ❌ 推给客户 | ❌ 推给客户 | ✅ 我们独占（L0/L1/L2 方案，见 `enrollment.md` §11） |
| **国内客户端覆盖**（豆包/Kimi/通义） | 部分 | ❌ 海外 registry 一个都没有 | ⚠️ 存在性检测可做，采集受加密限制 |

**读法**：汇智在**交付骨架**上领先（RBAC/授权/监控/错误码），shadow-ai-guard 在**审计视角**上领先（账号/覆盖率/预算）——
**两家都没做"记忆文件"这一层，也没人管跨网**。这两处是我们的空位。

## 4. 能力栈：四层 + 一个底座

```
L4  编排面   中枢即 MCP Server（对外可被任意 AI 驱动）
L3  用量层   token 聚合 / 日报 / 席位对账
L2  内容层   对话采集 + 记忆文件扫描 + 脱敏 + 风险命中        ← 首单武器
L1  资产层   装了什么 / 哪个账号 / 谁在用 / 采集源健康         ← 能见度
L0  底座     部署 / 入网 / 鉴权 / 审计 / 监控 / 授权 / 错误码   ← 敢不敢交付
```

**顺序原则**：先 L0 跑通 → 再做 L2（卖点）→ 立刻补 L0 剩余（能收钱）→ L3（续费）→ L4（平台化）。
**为什么不是先做完 L0 再做 L2**：L0 补齐要跨 RBAC、授权、监控、错误码四块，做完之前手上没有任何一页能演示。
先做出 L2 那一页，才有人愿意听你讲 L0。

## 6. 商业化：不照抄 500/台 + 3000/家

汇智这个价（20 人公司一次性 13,000）能成立，前提是**客户没有可用替代**。
而 shadow-ai-guard 虽免费却要 K8s + Loki + Grafana —— **"免费但装不上"等于不存在**，所以它的存在不影响汇智定价。

我们要抢的是"装得上但买不起"那一档：

| 档 | 内容 | 定价思路 |
|---|---|---|
| 基础版 | 单机/少量节点、能见度 + 基础审计 | 免费或极低，**用来进客户的门** |
| 标准版 | 全量采集 + 风险告警 + 日报 + RBAC | 中枢授权费做低 + 节点年费低单价 |
| 服务费 | 跨网打通、客户端库本地化、部署与培训 | **真正的利润来源** |

逻辑：既然有免费开源存在，**靠功能收高价站不住**；
靠"部署门槛 + 跨网 + 国内客户端库"收服务费才站得住——这三项恰恰是开源方案给不了的。

---

## 7. 明确不做

| 不做的 | 理由 |
|---|---|
| 实时阻断 | 架构做不到，汇智也做不到。卖之前讲清 |
| 云端会话采集（豆包/WorkBuddy 类） | 数据在厂商云端，本地取不到；除非厂商开放企业 API |
| 浏览器扩展路线 | 与端点路线是另一套工程，且是竞品主战场；可作为 V5 后的可选补充 |
| Nuitka 式冻 Python / 手写原生 JS 前端 | 我们是 Go，静态单文件天然更优，别为"看起来一样"放弃优势 |
| 默认明文 HTTP | 我们已有 `gencert` + TLS SAN，应当默认 TLS、显式降级 |
